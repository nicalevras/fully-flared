## Interfaces and migrations

- Export buttons use authenticated POST server functions and one-hour signed continuation cursors. A cursor binds the requester, target, row bounds, section, and position. Authorization is checked for every request.
- Downloads use JSON format version 2. Orders, items, addresses, returns, return items, and refunds are separate arrays joined by their record IDs. The file describes paged live reads, rather than a transactional snapshot. New rows above the initial bounds are excluded; concurrent changes can affect later reads.
- The browser assembles chunks and creates one download only after every request succeeds. Cancellation or a failed request produces no completed download. Browser memory remains proportional to file size; server reads and response sizes are bounded. A single oversized database record can exceed the normal page byte budget.
- The retired direct account export URL returns HTTP 410 and directs callers to the account export button. The old materializing helpers and admin export actions were removed after their callers migrated.
- Migrations `0039` and `0040` add privacy tracking and terminal outbox cancellation. Migration `0041` adds indexes for account and guest export traversal; `0042` indexes historical privacy-gap reporting. All four were applied locally only. Previously applied migrations were preserved.
- Atomic role changes depend on the current Better Auth database configuration. Cookie caching is explicitly disabled and secondary storage is absent. Recheck role/session hooks and invalidation when upgrading or changing that configuration.
